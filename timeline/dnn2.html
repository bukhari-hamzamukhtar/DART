Project Blueprint: V2 Ascension

Transitioning from a 2D mathematical demo to a Web-Socket driven, Multi-Agent Tactical Engine with Hierarchical Graph Intelligence and React/Tailwind rendering.

01 The Brain Upgrade — Ultra Instinct & Sub-Graphing
Hierarchical Sub-Graphs (The "Random Forest" of GNNs) AI Arch
Currently, the AI lumps all missiles into one giant graph(i believe). If a new missile appears, it skews the math for the entire calculation.

V2 Upgrade: We implement an Ensemble Graph Network(or dynamic graphs or whatever they are called). The main AI acts as the "Stem." When multiple threats appear, the AI spawns isolated sub-graphs (branches) for each distinct threat (e.g., Sub-graph A evaluates 1 Homing Missile; Sub-graph B evaluates 2nd Homing Missile; Sub-graph C evaluates a Ballistic).

The AI then runs a weighted aggregation (Attention Mechanism) across these sub-graphs. This ensures a slow ballistic missile 800px away doesn't distract the AI from a homing missile 50px away. It allows the AI to process layered threats dynamically without graph pollution.
Multi-Step Time Horizons
To stop the jet from dodging into walls, we replace the flat 10-frame lookahead with a Multi-Horizon Lookahead. The GNN now simulates 3 distinct futures per candidate move: t+10 (Immediate), t+30 (Mid), and t+60 (Strategic). It calculates a combined risk score, guaranteeing that an evasive maneuver doesn't leave it trapped in a corner 1 second later.
Continuous Local Learning
The Tesla Autopilot Approach: Every time you destroy the jet, the engine saves the last 300 frames of telemetry as a JSON log. A background Python script parses these "death logs," labels the AI's final moves as fatal, and fine-tunes the GNN weights. The longer you play, the more the AI learns to counter your specific playstyle.
02 Physics & Capabilities — Fluidity & Real Maneuvers
Expanded Action Space (Throttle & Triggers) Engine
The AI's action space expands from a 1D output [heading] to a 3D tactical output: [heading_delta, throttle_delta, maneuver_trigger].

  • Dynamic Throttle: The jet can now slam the brakes (drop to 20% speed to let a missile fly past) or hit the afterburners (150% speed but massively increased turn radius).
  • Time-To-Impact (TTI) Flares: Flares are no longer deployed randomly. The AI calculates the exact frame the missile will intercept its hull and executes a "Parry"—deploying flares at the absolute last millisecond to guarantee the missile bites the decoy.
Hard-Coded Famous Maneuvers
If the GNN detects a highly specific threat vector (e.g., two homing missiles closing from the rear), it can trigger specialized macro-animations:

1. Su-57 Falling Leaf: Jet kills throttle, rapidly oscillates heading left and right while dropping altitude, ejecting 3 flares per second. Missiles lose track due to sudden speed drop.
2. Vertical Stall (Cobra variation): Jet pulls 180 degrees, hits 0 speed, and drops a massive wall of flares before boosting in the opposite direction.
03 The Tactical Arsenal — Upgraded Player Weapons
Predictive Ballistic Launcher
The Sniper Logic: Instead of holding to aim, a single right-click captures the jet's exact (x,y) coordinates at that millisecond. The ballistic missile is fired at that static point at extreme velocity. It forces the player to predict where the jet will be, and punishes the jet if it hovers or stalls too long.
Cluster-Homing Swarm
The Area Denial Weapon: A new launcher type. On click, it ejects 5 to 6 micro-missiles in a flush, 45-degree V-shape spread (mirroring the flare logic).
Stats: 30% slower than standard homing missiles, but they fan out and slowly collapse around the jet, cutting off its escape routes and forcing it to use complex maneuvers to survive.
04 Visuals & UI — The Tailwind / WebSocket Pivot
Decoupling the Brain from the Body Full Stack
We abandon Pygame's rendering. Pygame is now purely a "Headless Physics Server." We spin up an asyncio WebSocket server that broadcasts the (x,y,heading,speed) of every object at 60Hz.

A React + Vite + Tailwind CSS frontend catches this stream and renders it using HTML5 Canvas or WebGL (Pixi.js). This unlocks AAA-level UI without lagging the AI math.

2D Faking 3D (Rotation & Tilt)
Because we are moving to WebGL/Canvas, we replace the cyan circles with actual high-res top-down jet sprites (PNGs).
The Math: The sprite rotates based on heading. To fake a "bank" or "tilt" during sharp turns, the web engine applies a CSS/Canvas Skew/Scale transform along the X-axis based on the turn_rate. The harder the AI turns, the more the wing dips visually.
Tailwind HUD & Menus
HTML/CSS overlay on top of the game canvas provides beautiful, glowing neon UI.
Includes: A live "Threat Level" graph, dynamic crosshairs that follow the mouse, and smooth blur-backdrop modal menus for "Play Again", "Exit", and "View Last Death Log".
05 V2 Implementation Roadmap
Phase 1: The Physics Extension (Python)
Refactor the existing Pygame script. Add Throttle logic to the Jet class. Implement the new Ballistic Sniper and Cluster-Homing swarm math. Test headlessly.

Phase 2: The Brain Surgery (PyTorch)
Update the scene-graph builder to handle Sub-graphs. Expand the GNN action space to output [heading, throttle, maneuver_id]. Add the 3-tier time horizon projection.

Phase 3: The Web Bridge (Sockets)
Strip out pygame.display entirely. Add the websockets library. Broadcast a JSON dictionary of the game state every 16ms (60fps). Catch player click inputs from the socket and feed them to the launchers.

Phase 4: The Canvas/Tailwind Frontend (Node.js/React)
Build the React app. Implement HTML5 Canvas drawing loop. Load Jet and Missile PNG assets. Apply the rotation and skew transforms. Build the Tailwind UI overlays (Play Again, Scoreboard).
