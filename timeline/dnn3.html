00Why this architecture — the academic story
What you're combining and why it matters for your grade
Current project: flat GNN where all objects (jet, all missiles, all flares) live in one graph. The model learns collision physics. One DNN concept.

V2 project: Graph Neural Network + Cross-Graph Attention. Two distinct DNN paradigms combined into one end-to-end trainable pipeline. Each missile gets its own isolated sub-graph processed by the GNN. The resulting threat embeddings are then scored and aggregated by an attention mechanism. The attention weights are differentiable and jointly trained with the GNN — this is the "end-to-end" claim.

The killer demo moment: the HUD shows a live bar for each active missile. Its height is the attention weight the AI assigns to that threat. When a nearby homing missile closes in, its bar goes to 100%. A distant ballistic in the corner drops to ~5%. You are watching the AI decide where to look. No other game project has this.
01New GNN architecture — exact class definitions and dimensions
Two new classes replace the single InteractionNetwork. The old class stays almost identical but gets a new encode() path that returns node embeddings instead of edge probabilities. Add one new class on top.
Class 1 — ThreatGNN (the sub-graph encoder)
Processes a single small graph: nodes = jet + one missile + flare particles within 200px of that missile.

Node features (5-dim): [pos_x, pos_y, vel_x, vel_y, obj_type]
obj_type: 0 = jet, 1 = missile, 2 = flare particle

Edge features (4-dim): [rel_pos_x, rel_pos_y, rel_vel_x, rel_vel_y]
Fully connected between all nodes in the sub-graph.

Architecture internals (unchanged from current):
EdgeModel: Linear(5*2+4=14 → 128 → 64 → msg_dim=32) with ReLU + LayerNorm
NodeModel: Linear(64+32=96 → 128 → 64) with ReLU + LayerNorm
3 MetaLayer steps (same as current num_steps=3)

New: global pooling head
After the 3 MetaLayer steps, mean-pool all node embeddings → Linear(64 → 32) → ReLU → 32-dim threat embedding h_i

Output: one 32-dim vector representing the danger profile of that specific missile threat.
Class 2 — CrossThreatAttention (the aggregator)
Takes K threat embeddings from ThreatGNN + 2 context scalars per threat.

Context per missile (2-dim): [normalized_distance, normalized_TTI]
distance = hypot(jet_pos - missile_pos) / 800 → clipped to [0,1]
TTI (time-to-impact) = distance / closing_speed, normalized by 5 seconds → clipped to [0,1]

Attention scorer: Linear(32+2=34 → 32 → 1) with ReLU, applied independently to each [h_i; c_i] → scalar score_i → softmax over all K threats → attention weight alpha_i

Aggregation: z = sum(alpha_i * h_i) → 32-dim attended context

Danger head: Linear(32 → 16 → 1) + Sigmoid → final danger probability in [0,1]

Empty case (no missiles): skip GNN, return danger = 0.0 directly. Handled with a guard in forward().

Output: one scalar danger probability + K attention weights (the weights go to the HUD).
Class 3 — NeuralEvasionBrain (the wrapper)
Wraps both modules for clean calling from the game:

brain = NeuralEvasionBrain()
danger, attn_weights = brain(sub_graphs, contexts)

Internally: loops over sub_graphs → ThreatGNN → stack embeddings → CrossThreatAttention → return.

Batching for inference speed: Instead of looping, uses torch_geometric.data.Batch.from_data_list(sub_graphs) to process all K sub-graphs in a single batched forward pass through ThreatGNN. This is O(1) GPU/CPU calls regardless of K. After the batch, split embeddings by graph index (batch.batch attribute) → feed to attention. Total inference: ~3-5ms for up to 8 missiles.

02Data pipeline — headless sim → JSON → training
Headless physics simulator — what it generates
Pure Python, no Pygame, no display. Runs at ~5000x real-time. Generates training examples.

Simulation parameters:
— Map size: 800×600 (matches game)
— 1 jet, random initial position, random heading
— Jet moves with random heading perturbations (±0.1 rad/frame, simulating a dumb dodger)
— 1–5 missiles spawned at random positions, homing or ballistic, random speeds 3.5–7.0
— Flares spawn randomly every 2–4 seconds, 8 particles per burst
— Run each simulation for 300 frames (~5 seconds at 60fps)
— Generate 8,000 simulations = 2.4M frames

What to log every 5 frames:
For each frame snapshot, log: jet state, all missile states, all flare states, and a binary label: does any missile hit the jet within the next 20 frames? (computed by running the physics forward 20 steps and checking circle-circle collision).

Collision label (the fix):
dist = hypot(missile.x - jet.x, missile.y - jet.y)
hit = dist < (jet.radius + missile.radius)
This replaces the random labels in the current notebook. Non-negotiable fix.
JSON schema per training example
{
 "jet": {"pos":[x,y],"vel":[vx,vy]},
 "missiles": [{"pos":[],"vel":[],"type":1},...],
 "flares": [{"pos":[],"vel":[]},...],
 "label": 0 or 1
}

One JSON object per line (JSONL format). Total file size ~150MB for 8k sims. Uploads to Colab in ~3 minutes.
Training data balance
Because the dumb jet often survives, ~70% of examples will be label=0. Apply class weights in BCE loss:

pos_weight = torch.tensor([0.7/0.3])
loss = BCEWithLogitsLoss(pos_weight=pos_weight)

Target: F1 > 0.80 on held-out 15% validation split. Anything above 0.75 is sufficient for the game to work well.
Graph construction from one JSON example
For each example with K missiles, build K Data objects:

for i, missile in enumerate(example["missiles"]):
  nearby_flares = [f for f in example["flares"]
    if hypot(f.x-missile.x, f.y-missile.y) < 200]
  nodes = [jet] + [missile] + nearby_flares[:6]
  # cap flares at 6 to bound graph size
  sub_graph = build_data_object(nodes)

All K sub-graphs share the same label (did any missile hit the jet). Batch them together with Batch.from_data_list(). The ThreatGNN encodes all K graphs simultaneously. Then attention aggregates.

04Game integration — what changes in main.py
Updated gnn_inference_worker — the full new logic
Step 1: Build candidate states
Same as before: 9 heading deltas, project jet position 10 frames forward per candidate.

Step 2: For each candidate, build K sub-graphs (one per missile)
For each of the 9 candidates × K missiles, build a Data object. Batch all 9K graphs together. One forward pass through ThreatGNN. Split results by (candidate, missile).

Step 3: CrossThreatAttention per candidate
For each candidate, feed its K embeddings + [distance, TTI] contexts into the attention module. Get danger_i and alpha_weights_i.

Step 4: Multi-horizon (t+10, t+30, t+60)
Only run the full pipeline on the top-3 safest candidates from step 3 (prune 6 candidates). For those 3, repeat with 30-frame and 60-frame projections. Final score: 0.6*d10 + 0.3*d30 + 0.1*d60.

Step 5: Wall + center penalties
Same as current: wall penalty = 10.0, center drift penalty = distance/800 * 0.1.

Step 6: Output to game
Push (best_heading, drop_flare_bool, attention_weights, lowest_danger) to decision_queue. The attention_weights go to the HUD renderer.
TTI calculation (used as attention context): For missile i at position (mx,my) with velocity (mvx,mvy) and jet at (jx,jy) with velocity (jvx,jvy): relative velocity = sqrt((mvx-jvx)²+(mvy-jvy)²). Closing speed = dot product of relative position and relative velocity, divided by distance. TTI = distance / max(closing_speed, 0.1). Cap at 5.0 seconds.
HUD — live attention weight bars
In the render loop, for each active missile i:

— Draw a small vertical bar in the top-right corner, 8px wide, up to 40px tall
— Height = alpha_i * 40 pixels
— Color: interpolate from green (alpha=0) to red (alpha=1)
— Label: "M1", "M2", "M3" below each bar
— If a missile's bar is near 100% and the jet is in danger mode, flash it

This is a live window into the GNN's reasoning. Add a text label "AI attention" above the bars.
05Five maneuvers — exact trigger conditions and movement math
All maneuvers are finite state machines. A global ai_maneuver variable has states: NORMAL, FALLING_LEAF, COBRA, BARREL_ROLL, JINKING, IMMELMANN. When in a non-NORMAL state, the GNN heading output is overridden by the scripted movement. A maneuver counter counts down frames. When it hits 0, state returns to NORMAL.
1 — Falling Leafdanger > 0.65
Trigger: danger > 0.65 AND count(missiles) >= 2 AND at least 2 missiles within 180px
Duration: 90 frames (1.5 seconds)
Movement: jet.speed = max_speed * 0.2. Heading oscillates: heading += sin(frame_counter * 0.4) * 0.6. This creates the characteristic side-to-side wobble. Flare deploy: every 18 frames, emit a 6-particle burst in a 180° rear arc.
Exit condition: early exit if frame_counter reaches 90 OR all missiles are dead OR danger drops below 0.2.
2 — Cobradanger > 0.72
Trigger: danger > 0.72 AND single missile within 100px closing head-on (dot product of missile velocity and jet-to-missile vector is negative)
Duration: 40 frames
Movement: Frames 0–20: jet.speed → 0.1 over 20 frames (lerp), heading rotates +π radians (180°) over 20 frames. Frames 20–25: deploy 14-particle flare wall, full 360°. Frames 25–40: jet.speed → max_speed * 1.2, heading continues in new direction.
Cooldown: 8 seconds before Cobra can trigger again (too expensive to spam).
3 — Barrel Rolldanger 0.4–0.62
Trigger: danger between 0.40 and 0.62 AND single missile within 200px
Duration: 72 frames (1.2 seconds)
Movement: heading += 0.15 every frame (constant angular velocity = circular path). Speed stays at 100%. No flares deployed — this is a pure geometry evasion, the circular path makes trajectory prediction hard. Draw a faint circle ghost on the trail to visually indicate the roll is active.
Why it works: Circular motion has no predictable straight-line intercept point, which breaks proportional navigation homing.
4 — Jinkingdanger 0.48–0.68
Trigger: danger between 0.48 and 0.68 AND count(missiles) >= 3 (multiple simultaneous threats)
Duration: 120 frames (2 seconds)
Movement: Every 10 frames, snap heading by a random value in [-0.45, -0.3, +0.3, +0.45] radians. Speed at 85%. No flares — conserve them for Cobra and Falling Leaf.
Why it works: Chaotic heading changes defeat homing missiles' turn-rate limit. Requires 3+ missiles because with fewer, Barrel Roll or GNN evasion is sufficient.
5 — Immelmannwall escape
Trigger: jet within 60px of any wall AND jet.speed > 2.0. Priority override — fires even if another maneuver is active (prevents the jet from dying to walls while executing a Cobra).
Duration: 30 frames
Movement: Frames 0–30: jet.speed = max_speed * 1.3 (afterburner), heading += π/30 each frame (smooth 180° reversal). No flares. After 30 frames, jet is traveling in the opposite direction at full speed, away from the wall.
Visual: The trail draws a clean U-turn arc, which is a distinctive visual signature that reads as intentional.
Priority stack — which maneuver wins when multiple trigger simultaneously
IMMELMANN > COBRA > FALLING_LEAF > JINKING > BARREL_ROLL > GNN_NORMAL

Implementation: check conditions in this order at the start of the decision cycle. First match wins. A maneuver in progress cannot be interrupted except by IMMELMANN (wall escape is always priority).
06New weapons and game mechanics
Predictive ballistic (Q key)
Right-click now fires a BallisticMissile at (jet.x, jet.y) at the exact moment of click — not at the mouse cursor. Fires at the jet's current position, forcing the player to time shots when the jet is where they need it. Change: 5 lines in the event handler.
Cluster swarm (E key)
On press: spawn 5 HomingMissile objects at angles [click_heading - 20°, -10°, 0°, +10°, +20°] relative to the direction from launcher to jet. Speed: 70% of normal. They fan out then converge. 6-second cooldown.
Jet sprite (visual polish)
Replace cyan circle with a rotated triangle: 3-point polygon with pygame.draw.polygon. The triangle's tip points in jet.heading direction. No PNG needed. During Barrel Roll, apply a slight x-scale compression using a surface transform to fake the bank angle.

08The pitch — what to say in 60 seconds at open house
"This is a hierarchical Graph Neural Network with cross-graph attention controlling a real-time AI pilot. Every object in the scene — the jet, each missile, each flare particle — is a node in a graph. But instead of one flat graph, each missile gets its own isolated sub-graph processed by the GNN, which outputs a 32-dimensional threat embedding. Those embeddings are then weighted by a learned attention mechanism that the model has never seen an explicit label for — it discovered on its own that nearby fast missiles deserve more focus than distant slow ones. You can watch that live in the top corner. The AI uses those threat scores to evaluate 9 possible maneuvers every 100ms and picks the safest one — and when the danger crosses specific thresholds, it switches to one of five pre-encoded fighter pilot maneuvers. Try to hit it."
