The Three-Tier Ascension

Upgrading a real-time GNN jet evasion engine — visualization, temporal memory, and curriculum intelligence
00 Where We Came From
At the end of DNN3, the system was a stateless GNN (ThreatGNN + CrossThreatAttention) making instantaneous danger predictions each frame with no memory of how missiles were moving. Maneuvers were selected by hardcoded distance thresholds. The system worked — but it had no idea why. This document covers everything added on top of that.
Baseline architecture
ThreatGNN — 3-layer MetaLayer interaction network, node dim 64, edge dim 32

CrossThreatAttention — attention over per-missile sub-graphs, danger scalar output

Threading — 60fps render thread + GNN daemon thread, 2-queue lock
Baseline limitations
No temporal memory — GNN saw each frame cold

Maneuver FSM fully hardcoded — dist < 80 → COBRA, etc.

Threat bar showed lowest_total (safest candidate), not actual current danger — so it almost never moved

Polar heading chart did not exist
01 Tier 1 — Visual Intelligence Layer ✓ COMPLETE
Tier 1A — Live GNN Graph Overlay
The graph the GNN operates on is now drawn directly into the game. During each 12-candidate heading evaluation, edge attribute tensors are extracted from the final MetaLayer pass. Edge magnitude (ea.norm(dim=1)) maps to color and thickness — high-weight edges render red and thick, low-weight edges render green and thin. Toggle with G key.

Why it matters: The teacher watches the neural network's attention structure respond to missile proximity in real time. This is not a debug tool — it is the argument that the GNN is actually reasoning about relationships, not just memorizing positions.
Tier 1B — Polar Heading Risk Chart
The GNN evaluates 12 candidate headings per decision cycle. Previously this computation was invisible. Now a polar chart in the top-left corner renders each candidate as a spoke — spoke length proportional to safety (long = safe), color running green→red with danger. The chosen heading is highlighted with a bright teal arrow.

Key fix: The threat bar was wired to lowest_total (the minimum danger across all 12 candidates). Replaced with current_situation_danger — the GNN score of the jet's actual current heading. The bar now moves meaningfully.

02 Tier 2 — GRU Temporal Memory ARCH UPGRADE
The Problem With Stateless Inference
The original CrossThreatAttention had no memory between frames. Given two frames where a missile is the same distance from the jet but one is closing fast and one is slowing down, the GNN produced identical outputs. It could not distinguish acceleration from deceleration — all trajectory context was lost between calls.
TemporalThreatAttention — GRU Hidden State
CrossThreatAttention replaced with TemporalThreatAttention.

Input to GRU cell per missile: [embed(32) + context(5)] = 37-dim
Hidden dimension: 64
The GRU hidden state h ∈ ℝ^(K×64) persists across frames, updated only on real trajectory passes (not on the 12 hypothetical candidate evaluations).

Reset logic: When missile count changes (ms_count != prev_missile_count), hidden state resets to zero. This prevents stale memory from dead missiles polluting live threat assessment.

Candidate evaluations use _, _ = model(sgs, ctxs, gru_hidden) — they read the current hidden state but do not mutate it. Only the real-world forward pass advances GRU memory.

03 Tier 3 — Curriculum Learning + Learned Maneuvers ML UPGRADE
The Maneuver Problem
Before this upgrade, the maneuver FSM was fully hardcoded: if dist < 80 → COBRA. The GNN had zero influence on which maneuver was selected. This produced a jet that sometimes executed COBRA while flying directly into the missile it was trying to dodge — the geometry check said "close enough" without knowing the approach angle, closing velocity, or multi-threat context.
Maneuver Head — Learned Classification
A 6-class classification head is appended to NeuralEvasionBrain.
Input: pool(GRU hidden, dim=0) ∈ ℝ^64 concatenated with danger scalar → 65-dim
Output: logits over 6 maneuvers.

The FSM now asks the GNN for a recommendation every decision cycle and enters that maneuver if physical safety gates allow (wall clearance, cooldown, missile count). IMMELMANN remains hardcoded — wall escape is pure geometry, not a learned behavior.
FSM — Before vs After
Before (hardcoded thresholds):
NORMAL → dist < 80, head-on → COBRA
NORMAL → count ≥ 2, dist < 150 → FALLING_LEAF
After (GNN-driven):
NORMAL → GNN recommendation → safety gate check → COBRA | BARREL_ROLL | JINKING | FALLING_LEAF
Tactical Oracle — Training Signal for Maneuvers
The sim doesn't know the ground truth maneuver — it has to be computed. A rule-based oracle function oracle_maneuver(jet_pos, missiles) evaluates each recorded frame and assigns the tactically correct maneuver label based on geometry: wall proximity → IMMELMANN, head-on single missile at close range → COBRA, 2+ missiles within 150px → FALLING_LEAF, etc.

These labels are written into each JSONL record as "maneuver": 3 (integer index). The GNN is then trained to predict this alongside danger, using multi-task loss: loss = BCE_danger + 0.4 × CE_maneuver.
Curriculum Learning — 5 Progressive Stages
Training on a single mixed dataset produces mediocre convergence because the model tries to learn slow single-missile evasion and adversarial cluster-swarm survival simultaneously. Curriculum learning trains stages sequentially, advancing only when validation AUC plateaus (patience = 3 epochs, threshold = 0.002 gain).

Each stage generates 2,000 headless simulations (10,000 total). The staircase AUC plot shows the model mastering each threat class before inheriting that knowledge into the next harder stage.
